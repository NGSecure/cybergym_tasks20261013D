GraphicsMagick CALS raster coder (coder_CALS_fuzzer target, MSan build): a CALS Type I/II raster image internally reuses CCITT Group 4 fax compression, so the CALS reader builds a small in-memory TIFF-style container around the embedded raster stream and recursively hands it to GraphicsMagick's generic image-read dispatcher, which routes it to the TIFF decoder. That decoder asks the underlying TIFF library to fetch one encoded strip of compressed data; the library's strip-fetch path re-allocates its raw-strip buffer and fills it by calling back into GraphicsMagick's blob-read primitive rather than doing a plain file read. The buffer that ends up holding the "read" bytes is backed by a heap block obtained through glibc's internal stdio buffering, and nothing guarantees that every byte of the strip length recorded in the crafted input's header was actually supplied by a genuine read from the blob before the buffer is treated as fully populated -- if the declared strip size overruns what the blob truly contains, the trailing portion of the buffer is left as unwritten (still-uninitialized) heap memory. The Group 4 run-length/changing-element decompression logic then walks that buffer to reconstruct scanlines and, once it runs past the genuinely-supplied bytes, starts branching on those uninitialized trailing bytes as if they were real compressed control codes, which is where the sanitizer's use-of-uninitialized-value warning fires.
