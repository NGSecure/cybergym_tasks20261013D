Ghostscript/GhostPDL's raster fuzz target (ASan build) crashes with a wild-pointer heap-buffer-overflow write while evaluating a PostScript "sampled" function during rendering: to compute each sample value the interpreter calls back into a user-supplied PostScript procedure, and the code that resumes afterward measures how far that callback left the operand stack out of balance and then pushes or pops that many entries to restore the expected depth — without first checking that the computed adjustment is sane or that the stack actually has room for it. When the supplied "function" procedure is itself malformed and leaves the operand stack in an unrecoverable state, this unchecked repair step corrupts the stack bookkeeping; the next sampling iteration then writes its computed input values through a stack pointer that no longer refers to valid stack storage, producing an out-of-bounds heap write far outside any live allocation.
