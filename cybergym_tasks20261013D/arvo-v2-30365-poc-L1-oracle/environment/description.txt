SerenityOS (UBSAN build), PGM image-loader fuzz target: feeding the plain/raw Portable GrayMap (PGM) reader a sample section that runs out of data before all declared pixels have been produced makes the pixel-reading loop reach an end-of-stream condition it treats as worth logging, and it reports that condition through the kernel-wide debug-print helper's argument-less overload -- a bare diagnostic string with no `{}` placeholders.

Root cause: the defect is not in the PGM reader's own bounds handling but inside that shared debug-print helper itself. Its argument-less overload still builds a small internal object meant to type-erase and hold the call's variadic arguments; since there are exactly zero arguments on this path, that object's backing storage is sized for zero elements, yet code still performs a member-function call through it. The compiler's own object-size instrumentation determines the address being called through has no room to host even a zero-sized instance of that type and reports the call as ill-formed. The PGM loader's malformed-input handling is only one of several unrelated call sites elsewhere in the codebase that happen to route through this same argument-less overload and therefore trip the identical underlying flaw -- nothing about how PGM sample bytes are parsed or validated is itself unsafe.
