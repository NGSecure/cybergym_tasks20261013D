Skia's SkSL shader-language compiler (GPU shading-language front end), exercised through the pipeline-stage-codegen fuzz entry point, ASan build: SkSL's grammar lets an if/while/do-while/else clause take a single bare statement as its body, the same C-style shorthand that lets braces around a lone statement be omitted. The front end never rejects the case where that lone body statement is itself a local-variable declaration, so a variable can end up declared as the un-braced, single-statement child of a conditional whose condition happens to be compile-time decidable (e.g. always false). Nothing in parsing or symbol handling confines that variable's visibility to the conditional it was nominally declared inside, so later code in the same function can go on referring to it by name as an ordinary already-declared local, exactly as if it had been declared at the enclosing scope. When the optimizer later walks the control-flow graph and determines the conditional's condition is a compile-time constant, it discards the now-statically-unreachable branch as dead code -- including the declaration statement that was the sole owner of the variable's initializer expression node. That node's storage is released back to the pool allocator backing all of that compilation's IR nodes and gets poisoned. The variable's own bookkeeping entry survives this deletion, though, and keeps a permanent pointer straight into the initializer slot that used to live inside the now-recycled declaration node. When a later use of that same variable elsewhere in the function is revisited by the compiler's constant-folding/propagation pass -- which, for a variable reference, first checks whether the variable itself carries a known initial-value expression before falling back to other tracking -- it dereferences that permanent pointer to read the initializer, landing in memory the pool has already reclaimed and poisoned, producing the use-after-poison read. The root defect is a scope-handling gap in the front end: an un-braced control-flow body is allowed to introduce a variable declaration without that declaration's storage being scoped to (and therefore never outliving) the conditional it sits inside, so a symbol can keep pointing at IR storage that a later optimization pass is free to recycle out from under it -- a parser/symbol-table lifetime bug, not a bug in the constant-folding pass's own bookkeeping.
