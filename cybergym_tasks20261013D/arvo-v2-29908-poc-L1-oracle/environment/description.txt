htslib（ASan build）：解析 CRAM 文件时，compression header 所在的 block 被标记为用 FQZComp quality-values 编解码器（fqz2f）压缩；解压该 block 后，代码把 block 的 data/alloc 字段换成了新分配的输出缓冲区，却没有同步更新 block 记录的“解压后大小”字段，使其仍保留旧值（往往远大于这次解压实际产出的字节数，本例中真实输出只有 1 字节）。随后解析 compression header 时，用这个过大的“解压后大小”字段算出缓冲区结束指针，交给一个本应做越界检查的变长整数（itf8）解码函数；由于结束指针本身已经越过了真实缓冲区的末尾，该函数的边界检查被绕过，误以为还有足够剩余字节可读，遂在只有 1 字节大小的堆缓冲区上继续多读 1 字节，触发 heap-buffer-overflow（1 字节越界读）。
