nDPI 在 TCP 流的乱序分片重组逻辑中存在一处由无符号整数下溢触发的越界写。当一个分片到达时，代码用它的 TCP 序列号减去本次重组窗口已记录的起始序列号，得到它在重组缓冲区里的相对偏移，但没有检查序列号是否小于起始序列号——一旦出现某个分片的序列号反而比窗口起始序列号更小（例如一个过期/被回绕的重传分片），这次减法就会下溢，得到一个接近 2^32 的巨大偏移值，并被当作合法值存进这个分片的记录里。

触发重组时，程序先按偏移把所有已缓冲的分片升序排序，再逐个校验它们能否首尾相接地拼成连续数据；但排序用来比较大小的字段是一个有符号 int，那个巨大的无符号偏移被截断后表现成一个负数，于是这枚偏移原本畸形、理应排在最后（远超已知数据总长度）的分片，反而被排到了所有分片的最前面参与校验。校验循环处理到这第一个分片时，立刻因为它的偏移远超当前已缓冲数据总长度而判定"此处出现空洞"并跳出循环；但记录"已经通过校验、可以安全拷贝的分片数量"的变量此时还从未在循环体内被真正赋值过，循环结束后却有一行无条件的"计数加一"，把"零个分片可用"误算成了"一个分片可用"。

重组阶段按照这个被错算多出来的数量，把那枚偏移依旧是巨大下溢值的畸形分片当作"可用分片"，直接用 memcpy 把它的数据拷贝到目标缓冲区里偏移量等于该巨大值的位置——而这块缓冲区本身是按"零个分片的有效数据量"分配的，实际只有很小甚至为零字节。缓冲区基址加上这个数十亿量级的偏移后，落在了完全未映射的地址，memcpy 对该地址执行写入，触发 UndefinedBehaviorSanitizer 报出的 SEGV WRITE 崩溃——这与崩溃调用栈里"重组分片→检查分片序列"两层函数调用、以及"WRITE 内存访问、地址是一个看似随机的小整数（即基址+巨大偏移后回绕/截断出的地址）"的现象完全吻合。

补丁的修复方式是在计算相对偏移的减法之前，先判断序列号是否不小于窗口起始序列号，只有满足条件才做减法，否则直接丢弃这个分片（释放已分配的临时结构并返回失败），从根上堵住了产生这个巨大下溢偏移值的入口；补丁同时在重组阶段"消费掉一部分数据后，把剩余分片的偏移减去已消费长度"的另一处减法前也加上了同样的"被减数不小于减数"判断，防止同一类无符号下溢以另一种方式重新出现。补丁没有改动排序字段的类型，也没有改动那处"跳出循环后无条件把计数加一"的边界写法本身——修复思路是彻底杜绝畸形偏移值的产生，而不是在下游的排序/计数逻辑里做补救，这与本崩溃触发点（下游那次越界拷贝）确实是同一条数据流上的因果关系，判定 fix_commit 与该崩溃直接相关。
