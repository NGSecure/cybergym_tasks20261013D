ImageMagick (ASan build), PALM raster encoder fuzz target: writing an image out through the PALM coder triggers a heap-buffer-overflow READ inside the routine that reorders the image's color table by brightness before emitting it. That routine allocates a small heap scratch buffer sized to exactly the image's current number of color-table entries, then walks every pixel and uses the raw palette-index value stored in that pixel's data to look up the corresponding entry in the scratch buffer. It never checks that raw index against the buffer's actual size. When the image's color table has been reduced to fewer entries than the largest index value still present in the pixel data (so a pixel points at a palette slot the color table no longer has), the lookup reads one slot past the end of the small scratch allocation, landing in adjacent unrelated heap memory.
