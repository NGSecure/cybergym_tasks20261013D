libssh2 (SSH client library, ASan build): during the key-exchange handshake, deciding whether a locally supported algorithm name is present in a peer-supplied, comma-separated algorithm list searches that list with a delimiter-scanning helper that treats the list as an ordinary null-terminated C string instead of honoring the length the caller passed in for it; the list itself is just a length-bounded slice carved out of the incoming key-exchange packet's heap buffer, not a string with its own terminator, so when the segment being scanned has no comma and no stray null byte before the buffer's real end, the scan keeps stepping forward past that boundary looking for a delimiter that was never guaranteed to exist within bounds, walking off the end of the heap allocation into adjacent redzone memory and producing an out-of-bounds read.
