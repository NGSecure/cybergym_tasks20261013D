A use-of-uninitialized-value warning (MSan) fires while ImageMagick pings a PICT-format image whose picture stream embeds a JPEG-compressed sub-picture, at the point where that decoded sub-picture is alpha-composited onto the PICT canvas. The PICT decoder recognizes the embedded-JPEG opcode, hands the raw JPEG payload to the JPEG decoder to produce a standalone in-memory sub-image, grows/color-converts the PICT canvas to match its dimensions and colorspace, and then composites the sub-image's pixels onto the canvas with a Porter-Duff blend that, per pixel, un-premultiplies the source color by its own alpha -- color divided by alpha, the division guarded against a near-zero denominator -- before combining it with the destination pixel. Root cause: right after the JPEG decode finishes, a colorspace-conversion step re-syncs the sub-image's own pixel cache, whose backing memory is a fresh, non-zero-filled aligned heap allocation; for at least one pixel, the channel value the compositor reads back from that sub-image (the color or alpha sample feeding the un-premultiply division) falls in a byte range the JPEG decode path never actually wrote, rather than genuine decoded pixel data. The un-premultiply division therefore consumes that leftover, never-initialized value instead of a real sample -- the sanitizer flags the read at the point the guarded reciprocal is computed, not any memory-bounds violation.
