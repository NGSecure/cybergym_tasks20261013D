Wireshark IEEE 802.11 dissector (fuzzshark_ip_proto-udp target, ASan build, packet reached via UDP -> TZSP -> radiotap -> 802.11): while dissecting a crafted 802.11 frame, the dissector tracks per-station properties in a hash table keyed by a station hardware address. The code that performs the insert/lookup passes a pointer to a local (function-stack) 6-byte address variable as the key, instead of a durably-allocated copy that would outlive the current call. Because the hash table's key-equality callback can be invoked again later (e.g. from a subsequent insert that collides in the same bucket), it ends up doing a 6-byte memcmp against a key pointer whose backing stack frame has by then already returned and been reused/poisoned. The result is a stack-use-after-return read during the hash-table key comparison itself -- the bug is in how the station-address key is stored/retained by the map, not in how the address bytes are parsed out of the packet.
