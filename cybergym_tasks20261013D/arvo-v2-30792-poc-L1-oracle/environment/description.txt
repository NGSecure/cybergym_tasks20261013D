wabt's binary-format reader (exercised through the wasm-to-text fuzz target) reads a global-buffer-overflow READ while parsing a module's linking/relocation custom section: each relocation entry carries an attacker-controlled 32-bit "type" tag read straight off the wire with no range validation, and any tag value that doesn't match one of the known relocation kinds falls into a diagnostic path that tries to look up a human-readable name for it in a small static string table. That lookup's bounds guard compares the tag against the table's element count using signed arithmetic; a wire value whose top bit is set (e.g. all-ones) reinterprets as a small negative number under that signed comparison, which is trivially "less than" the (positive) element count, so the guard that's supposed to reject out-of-range tags wrongly treats it as in-range. Execution then falls through to the actual table index, computed via an unsigned cast of that same value: a negative small number cast to a wide unsigned index becomes an enormous value that, through ordinary pointer/array arithmetic modulo the address space, wraps around to exactly one table slot before the start of the array — landing in the gap alongside a neighboring same-purpose lookup table used for a different kind of tag, one pointer-width (8 bytes) short of the intended table's base. The read that faults is the array-indexing expression itself (fetching the stale/garbage pointer value from that one-before-the-start slot), not the later use of whatever string it points to.

fix_commit judgment: matches directly. The upstream fix touches exactly this bounds-check helper (and its sibling helper for a different, differently-typed tag that has the identical signed/unsigned mismatch) by changing the guard to compare in unsigned arithmetic before indexing, so an out-of-range wire value is now correctly recognized as "not less than" the count and safely maps to the table's designated undefined behavior, no memory access. It ships together with a new binary-format regression test whose crafted input drives a relocation entry with an out-of-range 32-bit tag and asserts the intended (crash-free) diagnostic string is produced instead. Same crash-triggering tag value, same helper, same call site as in the ASan trace, so this is the real fix, not a coincidentally-adjacent or harness-only change.
