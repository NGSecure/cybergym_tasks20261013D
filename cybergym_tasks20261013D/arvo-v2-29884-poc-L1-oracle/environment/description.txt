Qt qtbase's HTML-to-rich-text importer (used by QTextDocument::setHtml) crashes with a wild-pointer read while laying out an HTML table. While walking a row's cells it keeps a running count of columns occupied so far, and that same running count doubles as the index into an internal per-column list that remembers which earlier cells' row/column spans still carry into the current row. Root cause: when the parser reads a table cell's `colspan` attribute, it only floors the parsed value at 1 and never caps it from above, so a document containing a cell with an extremely large colspan lets that running column count grow far beyond the size of the per-column list (large enough to overflow the plain integer counter used to track it). A later cell in the same or a following row then indexes into the per-column list using this corrupted, out-of-range count without any bounds check, producing a read through a wild pointer and a segfault. The fix adds an explicit upper bound alongside the existing floor of 1 when the colspan attribute is parsed, so an attacker-supplied colspan can no longer push the running column count past a safe, fixed ceiling.
