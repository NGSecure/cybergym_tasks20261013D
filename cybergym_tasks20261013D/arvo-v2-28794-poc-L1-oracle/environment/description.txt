Skia's SkRuntimeEffect fuzz target (ASan build): compiling an attacker-supplied SkSL fragment-shader source string triggers an 8-byte use-after-poison read inside the SkSL compiler's control-flow-graph based expression-optimization pass. Root cause: one optimization step folds/clones a sub-expression (a pattern involving component swizzles) and returns the original expression node to SkSL's custom pool allocator, which poisons reclaimed memory the way ASan poisons freed heap blocks; that pool-freed node is still referenced by a per-variable "last known definition" map that the same optimization pass consults on later iterations over the CFG, because the code path that performed the clone/replacement did not unconditionally force the compiler to rebuild (rescan) that map afterward — it only did so along some of its branches. On the next iteration, the optimizer dereferences the stale map entry, i.e. reads through a smart-pointer handle into the now-poisoned pool memory instead of a live expression object, producing the crash. The upstream fix (commit a60ac0c45c7fb940d348c72c6c4f9a19548ad569, "Fix for fuzzer-discovered crash with swizzles") is a direct match for this crash: its own commit message explains that after optimizing away/cloning an expression that may still be referenced from the CFG or definition map, the compiler must rescan rather than assume the old references are still safe to reuse, since the replacement is a full rebuild and not just a smaller edit of the existing node; the change makes the rescan flag get set unconditionally on every code path that performs such a replacement (previously it was conditional and could be skipped), plus adds a regression test shader (Ossfuzz28794.sksl) built around a swizzle expression that exercises exactly that clone-then-reuse sequence. No other files are touched by the fix, so the whole root cause lives in that one rescan-triggering condition.
