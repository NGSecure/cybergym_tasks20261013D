Decoding a still AVIF image whose color-information box declares an unusual/uncommon CICP color-primaries + transfer-characteristics code pair that the plug-in's color-management path does not map to any of its named built-in color spaces: on this fallback path the handler instead tries to build a custom color space directly from four raw chromaticity coordinate pairs (the red/green/blue primaries plus the white point) that it fills in from the parsed color box. For this particular unrecognized primaries code, the code path that populates those four coordinate pairs leaves one of them only partially assigned before the custom color space is constructed anyway. The color space constructor's own sanity check, which inspects each supplied coordinate pair to decide whether the primaries form a usable triangle, ends up reading the not-yet-assigned coordinate, so the validity decision is made from uninitialized stack memory instead of a real chromaticity value taken from the file.
