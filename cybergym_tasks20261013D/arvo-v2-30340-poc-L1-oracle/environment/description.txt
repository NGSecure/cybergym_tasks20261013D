The crash happens directly inside the routine that performs the right shift itself, at the point where it writes the shifted digits back into the destination big-number's storage without first (re-)checking that this storage is still valid and large enough for the output before writing into it. In this particular reproducer, the destination object's backing memory had already been released earlier in the same test case -- freed when an unrelated big-number value sharing that same storage was cleaned up -- so the shift's digit-writing loop ends up storing through a stale pointer into memory it no longer owns, instead of into freshly validated space.
