SELinux's CIL policy compiler (secilc, AddressSanitizer build) aborts on an 8-byte stack-use-after-return read raised while a parsed CIL policy tree is being torn down. The crash needs a `validatetrans` statement whose constraint expression contains a nested list operand, produced by a helper that flattens one operand of the expression into its own sub-list before linking it into the parent expression. That linking step records a reference to the wrong thing: instead of the sub-list itself, it stores the address of the local stack variable that was holding the sub-list's pointer, so the parent expression carries a pointer into the helper's own stack frame rather than into the sub-list's storage. As soon as the helper returns, that stack slot is reclaimed and its contents become meaningless, but the recorded reference in the parent expression is never corrected; when the policy is destroyed and the code that frees the parent expression reaches this entry and tries to recurse into it as a nested list, the very first field it reads back out of the now-defunct stack slot lands squarely in memory the sanitizer has already marked as belonging to a returned frame, and the read is flagged immediately.
