c-blosc2's decompression context can carry a cached, digested copy of an embedded dictionary across chunks, freeing the previous digest and re-digesting a new one whenever a chunk with the "uses a dictionary" flag is decoded. When freeing the stale digest, the code releases it but does not immediately clear the context's pointer to it; the pointer is only overwritten a few lines later once a fresh dictionary has been validated and successfully re-digested. If any of the sanity checks on the new dictionary's declared size (too small, larger than the configured maximum, or larger than the input left to consume) fails in between, the function returns early — leaving the context still holding the address of the digest it just freed, without ever nulling it out. When the context is later torn down, the teardown path sees a non-NULL pointer and frees it a second time, and the digest-freeing routine itself reads from the (already-freed) object's fields while releasing its internal structures — a use-after-free read.
