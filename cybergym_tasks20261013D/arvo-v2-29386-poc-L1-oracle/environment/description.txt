Poppler's Qt PDF-to-PS conversion fuzz target (MSan build): converting a PDF page that embeds a TrueType font to PostScript triggers a use-of-uninitialized-value warning while re-encoding that embedded font as a Type 42 font program.

Root cause: the routine that assembles the Type 42 font program's table directory works in two passes over the set of candidate sub-tables. The first pass scans which sub-tables will end up being included and derives a count of how many entries the directory is expected to hold; a fixed-size scratch array on the stack is implicitly sized against that expected count. The second pass then actually walks the same set of candidate sub-tables again and, for each one it successfully resolves, writes one entry into that scratch array and advances a separate running tally of how many entries were actually written. Under certain malformed or unusually sparse table layouts, the second pass ends up writing fewer entries than the first pass's expected count predicted, so the running tally falls short of it.

The code that follows immediately afterward — building the on-the-wire table directory bytes — trusts the first pass's (now too-large) expected count rather than the second pass's actual tally, and loops over that many entries. For the extra iterations beyond what was actually written, it reads scratch-array slots that were never assigned any value in this invocation — leftover bytes from whatever the stack held before the function was entered. Those bytes are treated as if they were legitimate table-directory fields (tag/checksum/offset/length) and are handed to a generic byte-by-byte string-formatting helper that renders them as hexadecimal text; that helper's underlying integer-to-text conversion step consumes each byte as numeric input, which is what MemorySanitizer flags as a read of uninitialized memory.

The fix_commit's change: right after the second pass finishes writing entries (and before the table-directory bytes are assembled), it adds a check comparing the actual tally against the first pass's expected count; if the actual tally came up short, the expected count is clamped down to match reality (with a diagnostic warning), so the subsequent directory-building loop can no longer walk past the entries that were genuinely written. This directly closes the gap that let unwritten stack bytes be read and formatted.
