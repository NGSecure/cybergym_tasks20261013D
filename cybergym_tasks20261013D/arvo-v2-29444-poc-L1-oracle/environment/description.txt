Skia's SkSL shader compiler (skruntimeeffect fuzz target, ASan build): compiling a runtime-effect SkSL program whose body contains an expression that gets duplicated when the compiler's function inliner substitutes a call site with its callee's body triggers a genuine heap-use-after-free (the freed object is torn down through a real `operator delete`, not merely marked poisoned inside an arena). Root cause: while first converting the callee's source into IR, one of its subexpressions (a nested index/subscript access buried inside a call argument, itself inside a chain of binary operators) allocates a fresh synthetic type object on the heap and registers it as a symbol owned by the *local*, block-scoped symbol table that exists only for that particular nested statement. When the inliner later clones this expression tree into the caller at the call site, it duplicates the expression nodes but leaves the cloned node's type pointer aliased to that same original type object instead of copying the type into a symbol table that will still be alive once inlining is done. Once the callee's original local block scope is subsequently torn down — its symbol table's refcount drops to zero and its owned symbols, including that type object, are genuinely deallocated — the caller's inlined copy is left holding a dangling pointer to freed heap memory. A later optimizer pass that walks the function's control-flow graph doing constant-folding/algebraic simplification then inspects the type category of an operand built from that inlined, cloned expression, and the read through the dangling pointer is what ASan reports as a heap-use-after-free.
