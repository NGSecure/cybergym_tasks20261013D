matio's HDF5 v7.3 (.mat file) reader (libFuzzer build under MSan): while gathering the info for a cell array, the reader reads the array's object-reference values into a plain, uninitialized heap buffer and, without checking whether that read actually succeeded, proceeds to dereference every slot of the buffer as if it were a live HDF5 object reference regardless of outcome. Following one of these unvalidated/leftover reference values into the file's group hierarchy causes HDF5's own group-name resolution to visit a symbol-table entry whose link-name field was only ever partially written out by HDF5's own decoding of that entry; the visiting code then measures the length of that name, reading uninitialized bytes in the process and producing a use-of-uninitialized-value report deep inside HDF5's own group-traversal code.
