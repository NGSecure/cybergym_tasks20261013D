matio's HDF5 v7.3 (.mat file) reader (libFuzzer build under ASan): while recursively reading a struct's character-array field, the reader opens that field's dataset and asks HDF5 to read its full contents into a buffer it sized from the field's own recorded dimensions. The dataset's raw data is stored inline inside its object header (a "compact" storage layout HDF5 uses for small datasets), and on a crafted file whose object-header metadata makes the dataspace extent wildly inconsistent with how much data was actually stored inline, HDF5's own routine for gathering that inline data computes the amount to copy from the attacker-controlled extent rather than from the small buffer it actually allocated to hold the inline copy. The resulting bulk byte-copy reads far past the end of that small heap allocation — well over a hundred megabytes past a buffer only a few dozen bytes long — producing a heap-buffer-overflow read.
