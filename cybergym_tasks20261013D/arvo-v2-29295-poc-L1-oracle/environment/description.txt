c-blosc2's in-memory frame decoder, when asked to fetch a specific chunk lazily out of a super-chunk opened directly from a raw serialized-frame buffer, first resolves that chunk's byte offset via the frame's compressed offsets table (itself read successfully) and then, for the in-memory case, computes the chunk's start address as `frame_base + header_length + offset` without checking that this address plus the few bytes it is about to read actually lie inside the buffer. The code immediately swaps/reads a 32-bit compressed-size field from that computed address. Because the per-chunk offset value comes straight from attacker-controlled input and is never bounds-checked against the frame's real size before this pointer arithmetic, a crafted offset drives the read far outside the allocated buffer, producing a wild-address read.
