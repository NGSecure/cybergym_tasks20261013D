firebase-ios-sdk's Firestore core-serializer fuzz target (ASan build) aborts with an invalid-free: while turning a crafted serialized google.firestore.v1.Value protobuf message into an in-memory nanopb-generated struct, the vendored nanopb decoder's dynamic-allocation path for a length-delimited (bytes-typed) field ends up calling realloc() on a pointer value that was never actually handed out by malloc() in the first place -- a wild, garbage address rather than a null or a genuinely nanopb-owned previous allocation -- so ASan's realloc wrapper aborts with "attempting free on address which was not malloc()-ed" instead of growing the buffer. The bad pointer is consumed one call *before* the fuzz harness reaches its own separate, higher-level decoding step that turns the parsed proto into Firestore's internal value representation: the crash happens purely during the low-level "parse raw bytes into a proto struct" call, so none of the surrounding application-level decoding logic is on the crash path at all -- the fault is fully contained inside the bytes-field allocation/growth logic of the third-party protobuf-parsing layer itself, triggered by a particular malformed field encoding in the input.
