wolfSSH server-side SSH user-authentication handling (ASan build): when a client authenticates with an RSA public key, the server reads two length fields straight off the wire (for the public modulus and exponent) and passes them, together with pointers into the received packet, directly into wolfCrypt's big-number import routine to build the RSA key object — without first checking that either length is bounded by how many bytes are actually left in the packet. Root cause: because the modulus length is attacker-controlled and unvalidated, it can exceed the fixed internal capacity of the destination big-number representation. The import routine's own overflow-handling logic then advances its source read pointer into the caller-supplied buffer by the excess amount before copying bytes in, and since that excess is computed straight from the unvalidated, arbitrarily large length, the read pointer can be pushed far past the end of the small key-blob buffer into unmapped memory — so the following byte-by-byte copy loop dereferences invalid memory and the process dies with a wild-address-read segmentation fault.
