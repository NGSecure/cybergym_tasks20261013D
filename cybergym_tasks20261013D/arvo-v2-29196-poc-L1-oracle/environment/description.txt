A use-of-uninitialized-value warning (MSan) fires while ImageMagick resizes a decoded gradient-format image whose pixels carry an alpha channel, inside the color-normalization step of the resampling filter's second pass. The general-purpose resize routine performs a scale in two separable filtering passes: whichever axis has the larger scale factor is filtered first into a freshly heap-allocated intermediate image buffer, and the second pass then reads that intermediate buffer to produce the final output along the remaining axis. Wherever a pixel carries alpha, each pass computes a per-output-pixel normalization weight by summing every contributing input pixel's filter weight multiplied by that pixel's alpha value, then reciprocal-scales the blended color sum by that accumulated weight (guarded against dividing by a near-zero value) to undo the alpha premultiplication. Root cause: the intermediate buffer's backing memory comes from a plain aligned heap allocation that is never zero-filled, and for at least one pixel the first pass's per-channel write path -- gated by a clip/write-mask check that can skip the normal blend-and-write step for a pixel -- does not end up writing that pixel's alpha channel at all, leaving whatever leftover byte pattern the allocator handed back. The second pass's weight-accumulation loop then reads that never-actually-written alpha value as if it were real pixel data and folds it into the normalization sum, so the value handed to the divide-by-near-zero guard before the final color scaling is itself uninitialized -- the read is what the sanitizer reports, not any out-of-bounds access.
