Also part of AV1's in-loop post-processing inside AVIF decoding, running before the deringing/restoration stages: the deblocking filter walks the frame's internal vertical block edges and, for edges it classifies as needing the widest available smoothing kernel, reads several samples on each side of the edge to decide how strongly to blend across it. The frame's working pixel buffer is allocated fresh per coded frame at an internally padded size (rounded up to the filtering/prediction block grid) rather than at the file's exact visible picture size, and block reconstruction only ever writes the visible-picture portion of that buffer, leaving the padding margin with whatever the fresh allocation happened to contain. Because the deblocking pass walks edges based on the padded buffer's geometry rather than on which samples reconstruction actually touched, near the padded border it ends up folding some of that never-written padding into its edge-strength decision and its blended output, so the filtered pixel value depends on memory that was never assigned.
