nDPI's packet-processing fuzz target (ASan build) triggers a heap-buffer-overflow READ while dissecting a crafted QUIC packet whose Client Hello (CHLO) tag table contains a UAID entry: the tag-table walker computes each tag's absolute start position as the sum of a running tag-offset base, a per-tag relative offset, and the tag's declared length, then compares that sum against the total size of the decoded crypto-data buffer to decide whether the tag actually fits inside it. Every operand in that sum is a 32-bit unsigned integer, so a crafted combination of base/offset/length values can make the addition wrap around 2^32 and come out numerically smaller than the buffer size even though the real, un-wrapped position lies far past the buffer's end. When the wrapped comparison spuriously reports "in bounds," the walker treats the forged length as trustworthy and hands a pointer into the buffer, together with that oversized length, down to the HTTP-layer helper responsible for copying out the User-Agent string. That helper allocates a destination exactly sized to the given length and does a bounded copy of that many bytes starting at the given source pointer — the copy itself is internally consistent, but because the length it was told to copy was never genuinely validated against the true remaining size of the source buffer, the read walks far past the end of the underlying heap allocation, producing the observed out-of-bounds read of several hundred bytes.
