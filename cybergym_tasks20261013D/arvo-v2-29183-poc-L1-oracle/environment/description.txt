A 4-byte heap-buffer-overflow WRITE fires while Skia's GPU circle-blur mask filter builds the blurred-edge intensity profile texture that approximates a Gaussian falloff along a circle's radius. That texture-building path first turns the requested blur sigma into a step count for a discrete half-Gaussian convolution kernel, then allocates one contiguous scratch buffer sized to hold that half-kernel, a matching running/summed-area table, and a separate, wider array of per-x-coordinate vertical-kernel evaluations, and finally walks through and fills the half-kernel portion of that buffer one float at a time, in a tight loop bounded by the same step count used to size the allocation. That step count is derived purely from the sigma value with no upper bound and no finiteness check: earlier in the call chain, the effective shape radius that sigma gets scaled against is validated only against being "too close to zero," never against being infinite or not-a-number, so a degenerate draw whose radius resolves to a non-finite value lets a non-finite sigma flow all the way down into the step-count derivation. Converting that non-finite value to an integer step count yields an out-of-range/garbage magnitude, and this garbage magnitude is then used twice, inconsistently: once inside signed-integer arithmetic that computes the size of the shared scratch allocation (where the arithmetic overflows and wraps down to a small, unremarkable-looking size that actually gets allocated), and a second time, completely unclamped, as the loop bound for filling the half-kernel array. The fill loop therefore keeps writing four bytes at a time well past the end of the much-smaller buffer that was actually allocated, and the write AddressSanitizer reports is simply the first one to land immediately past that undersized allocation. Root cause: a degenerate (infinite/NaN) circle radius is never rejected at the point where it first enters the blur-profile computation, several call-frames above where the overflow write itself occurs, so the integer size used to allocate the shared kernel buffer and the integer bound used to fill it are computed from the same tainted value but diverge once integer overflow enters the picture — one saturates/wraps small, the other stays effectively unbounded.
