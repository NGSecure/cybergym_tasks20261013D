rdkit 在把 Marvin/MDL 分子文件里内嵌的 SMARTS 片段转换为分子对象前，会先对该 SMARTS 字符串做一次预处理：逐字符扫描，用一个栈式容器记录当前处于"顶层 / 圆括号分支 / `$(...)` 递归子模式"中的哪一层，遇到左括号（含 `$(`）就压入一个新的层标记，遇到右括号就无条件弹出栈顶标记去判断刚结束的是哪一层。根因在于这个"遇右括号必弹栈"的逻辑完全不检查栈是否还有内容可弹：当输入的 SMARTS 里出现比左括号更多的右括号（例如经模糊测试变异后产生的一长串不成对的 `)`）时，多余的右括号会先把预处理开始时压入、本应贯穿全程存在的最外层标记也弹掉，使栈变为空；后续再遇到右括号，代码依旧对着这个空栈取栈顶元素并弹出，这是一次未定义行为的操作——此时"弹出"实际释放的并非堆上分配的链表节点，而是该栈容器自身内嵌在其所在函数调用帧（也就是栈内存）里的哨兵/末端节点。于是程序对一个从未经过 `malloc` 分配的栈地址调用了 `operator delete`，被 ASan 判定为 attempting free on address which was not malloc()-ed（invalid-free / bad-free）而异常终止。

fix_commit 判断：该 commit 与本崩溃直接相关——它在 SMARTS 预处理函数里，对每次处理右括号之前新增了一次判空/判层校验（栈为空，或栈顶仍是最外层标记时，直接放弃这次"智能预处理"、原样把输入串交还给下游真正的 SMARTS 语法解析器去报语法错误，而不是继续弹栈），并附带了一条用畸形输入（含多余右括号的字符串）驱动整个解析入口、断言其能安全返回而不崩溃的回归用例，二者合起来精确堵住了"右括号多于左括号导致对空栈弹出、进而释放栈内嵌哨兵节点"这条路径。同一 commit 里还顺带修了其他几处不相关问题（一处报错信息里下标写错的小笔误、pickle 反序列化时环信息缺越界校验、以及原子/键替换后书签指针未同步更新），这些改动分布在别的文件/函数里，均不在本崩溃触发的调用路径上，属于同一次提交里捎带的独立修复，与本崩溃机制无关。
