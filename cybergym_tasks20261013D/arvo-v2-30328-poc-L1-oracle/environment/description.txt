relic (an arbitrary-precision / cryptographic bignum library), exercised through the cryptofuzz bignum-calculus fuzz target: an ASan heap-buffer-overflow WRITE of 8 bytes. It surfaces while a computed big-number result is being converted into a printable digit string, through a loop that repeatedly divides the value by a small radix and peels off one output digit per step. Each such division step allocates its own scratch quotient object using a fixed default capacity rather than sizing it to the magnitude of the value actually being divided, then writes one output digit for every digit the input value has into that freshly allocated scratch object. When the value being stringified is large enough that its digit count exceeds this fixed default capacity, the digit-writing loop runs past the end of the scratch allocation and corrupts adjacent heap memory.
