c-blosc2's in-memory frame decoder (reached when a super-chunk is opened directly from a raw serialized-frame buffer, e.g. by the decompress-frame fuzz target) suffers an out-of-bounds read while walking the frame's metadata-layer index: the routine that sanity-checks the frame's self-declared header-length field only rejects a header length that exceeds the frame's self-declared total length, so a crafted frame whose header-length field is a negative number (while the total-length field is set consistent with the real buffer size) trivially satisfies that comparison and is accepted as well-formed. Parsing then proceeds into the metadata-layer walker, which reads a per-entry content-offset value straight out of the header bytes and immediately dereferences the buffer at `base + offset` to check for a marker byte, without ever validating that offset against the header length, the total length, or the buffer's real size — so an attacker-chosen offset drives a wild pointer read far outside the allocated buffer.
