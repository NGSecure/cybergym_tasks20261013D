c-blosc2's in-memory frame decoder locates the compressed per-chunk offsets table for a super-chunk that was opened directly from a raw serialized-frame buffer by simply adding the frame's self-declared "chunks section size" header field to the frame's base address and header length — with no check that this arithmetic stays inside the buffer that was actually supplied. The resulting pointer is then handed straight to the low-level routine that decodes items out of a compressed buffer, which begins by reading the very first header byte at that address to determine the format version. Because the "chunks section size" field is taken verbatim from attacker-controlled input, a crafted frame can make this computed address land completely outside the allocated buffer, so the first byte access in the item-decoding routine is itself a wild-pointer read.
