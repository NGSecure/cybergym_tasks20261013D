ImageMagick's MVG (Magick Vector Graphics) drawing-primitive interpreter (encoder_mvg_fuzzer, ASan, 32-bit build) crashes while expanding a crafted elliptical-arc drawing command into its point-sampled polyline representation. Before writing each sampled point into the shared heap buffer that holds all pending drawing primitives, the interpreter is supposed to first compute how many points the arc will expand into and grow that buffer to fit; the growth check performs this sizing arithmetic by narrowing a floating-point point-count/extent value down to a fixed-width integer without first verifying the value survives that narrowing exactly, so for an arc whose computed point count is large enough to lose precision (or overflow) in the narrowing, the check reports the buffer as already large enough (or resizes it to a truncated, too-small element count) instead of failing safely. The point-expansion loop then keeps writing one drawing-primitive record per sampled arc point, trusting that earlier "size is sufficient" result, and eventually writes a primitive-info field past the end of the actual (too-small) heap allocation -- a 4-byte out-of-bounds heap write.
