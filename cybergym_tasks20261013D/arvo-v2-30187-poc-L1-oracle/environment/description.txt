wolfSSH (ASan build): while acting as the SCP file-transfer source and waiting for the peer's single-byte transfer-confirmation reply on an already-open channel, the server reads incoming channel data into a fixed-size stack buffer, capping the read length at exactly that buffer's declared capacity. Root cause: after the read, the code unconditionally appends a trailing NUL terminator one position past the number of bytes actually read; when the peer supplies a reply long enough to make the read fill the buffer completely (read length equal to the buffer's size), that terminator write lands one byte past the buffer's end, producing a 1-byte stack-buffer-overflow write.
