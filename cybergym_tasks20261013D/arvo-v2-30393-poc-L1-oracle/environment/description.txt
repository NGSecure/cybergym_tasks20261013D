nDPI 的 TLS Client/Server Hello 解析逻辑在构造用于协议指纹识别的 JA3 摘要字符串时，把密码套件列表、TLS 扩展号列表、椭圆曲线点格式列表等若干可变长字段依次以格式化写入的方式追加进一个固定 1024 字节的栈上缓冲区，每次追加循环都用“缓冲区总容量减去已写入长度”作为下一次写入允许的剩余空间传给格式化写入函数，并把该函数的返回值直接累加到已写入长度计数器上。根因：这个返回值是“若空间足够本应写入的字符数”，而不是实际写入的截断后字符数；扩展号/密码套件的数量来自报文本身、其允许上限远大于该缓冲区容量，当一个 Server Hello 报文携带足够多的 TLS 扩展号时，追加扩展号的那个循环仅在单次写入返回非正值时才提前退出，从不检查累计长度是否已经越过缓冲区容量，于是这个计数器在若干次迭代后被推过了缓冲区的实际大小；此后再计算“剩余空间”时，无符号的容量减法发生下溢，变成一个巨大的数，使下一次格式化写入误以为还有海量可用空间，从而不做任何截断地继续往后写，越过该栈缓冲区末尾覆写紧随其后的多个栈局部变量。修复：给密码套件、TLS 扩展号、椭圆曲线点格式、ALPN 后缀等每一处追加循环都补上“累计长度仍小于缓冲区容量常量”这一显式循环条件，在 Server Hello 与 Client Hello 两条构造路径上都逐一补齐，使循环在字符串写满之前就提前停止，从根本上避免那个被污染的剩余空间参数被算出来；同一次提交里还顺带修了另一个不相关模块里的一处名称解码长度计算错误，与本次崩溃无关。
